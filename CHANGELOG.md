# Changelog

## 1.2.4

### Безопасность
- Деинсталлятор удаляет только файлы, которые поставил установщик. Раньше он удалял всё содержимое папки установки,
  и если её выбрали вручную (например, `C:\Program Files` или папку с документами), пропали бы и чужие файлы.
- Автозапуск с правами администратора (задание Планировщика) создаётся, только если программа установлена в `Program Files`.
  Portable-копия в папке, куда может писать пользователь, теперь запускается через раздел реестра `Run` с обычными правами:
  иначе любая программа могла бы подменить exe и получить права администратора без запроса UAC.
  Такое задание, созданное прежними версиями, заменяется при следующем запуске с правами администратора.
- Задание Планировщика регистрируется через API, без временного XML-файла, который можно было подменить.
- Временный файл конфигурации с паролем доступен только текущему пользователю, администраторам и SYSTEM
  и удаляется при запуске, если остался после сбоя.
- Release-сборка ищет `trusttunnel_client.exe` только рядом с собой, а не в родительских папках (например, `C:\client`).
- Ссылки `tt://` с пробелами, кавычками и обратной косой чертой не принимаются; из приложения открываются только ссылки `https://`.

## 1.2.3

### Исправлено
- Серверы с протоколом HTTP/3 показывались «недоступными», если на сервере закрыт TCP: пинг всегда мерил TCP-подключение.
  Теперь для HTTP/3 пинг идёт по UDP — запрос согласования версии QUIC, без авторизации и без установки соединения.

## 1.2.2

### Исправлено
- Установщик завершался ошибкой «Вызывающий поток не может получить доступ к данному объекту…»:
  состояние галочки «Ярлык на рабочем столе» читалось из фонового потока.

### Изменено
- Меньше поводов для ложных срабатываний антивирусов:
  - ярлыки создаются через системный интерфейс `IShellLink`, а не через `WScript.Shell`;
  - деинсталлятор больше не удаляет себя через `cmd` с задержкой `ping`: Windows удаляет его при следующей перезагрузке;
  - у exe заполнены сведения о файле (описание, издатель, авторские права).

## 1.2.1

### Исправлено
- Кнопка «Проверить пинг» не показывала, что идёт замер: во время проверки оставалось старое значение, а новое приходило за доли секунды
  и выглядело так же. Теперь в списке на время замера стоит «…», кнопка крутится и неактивна, а в подсказке видно время последней проверки.
- Ошибка при выходе из приложения, если клиент сообщал о завершении уже после удаления значка в трее.

## 1.2.0

### Добавлено
- Выбор исходящего адаптера для режима VPN (TUN): подключение к серверу идёт через выбранный адаптер (параметр клиента `bound_if`).
  В списке только адаптеры со шлюзом; если выбранный адаптер недоступен, подключение не запускается.
- Журнал подключений как во Flutter-клиенте: домен, адрес, протокол, решение (VPN / Обход / Блок) и трафик по каждому соединению,
  с поиском. Работает на уровне журналирования «Отладка». Прежний текстовый журнал называется «Журнал клиента».
- Пинг серверов: время TCP-подключения к адресу сервера в списке, обновляется кнопкой и раз в минуту при открытии экрана.
- Автопереподключение, если клиент неожиданно завершился: паузы 2–30 с, до 10 попыток, сразу при появлении сети.
- Проверка обновлений на GitHub при запуске (раз в день) и кнопкой на экране «О программе».
- Расширенные настройки: anti-DPI и отключение проверки сертификата для сервера; MTU, изменение системного DNS
  и постквантовый обмен ключами для подключения.
- Резервная копия: экспорт и импорт серверов, профилей и исключённых маршрутов. Пароли сохраняются только
  при заданном пароле копии (AES-256 + HMAC, ключ из PBKDF2-SHA256).
- Сборка и публикация релизов в GitHub Actions по тегу `v*`, необязательная подпись exe.

### Изменено
- Вывод клиента обрабатывается пакетами, интерфейс не подтормаживает на подробном журнале.
- `scripts\package.ps1` заменяет только собираемую версию и не трогает запущенную portable-копию с данными.

## 1.1.0

### Добавлено
- Локальный SOCKS5-прокси как альтернатива VPN (TUN): порт, доступ из локальной сети, логин и пароль.
  В этом режиме на экране серверов показывается адрес прокси.
- Выбор сетевого адаптера для доступа к прокси из локальной сети: прокси слушает только IP выбранного адаптера.
  Если адаптер недоступен, подключение не запускается.
- Тёмная тема, режим «как в системе» с отслеживанием настроек Windows, тёмный заголовок окна и меню в трее.
- Английский язык интерфейса.
- Запуск без прав администратора: приложение перезапускается с повышенными правами, только когда это нужно для режима VPN (TUN).
  Добавлен параметр «Всегда запускать от имени администратора».
- Установщик (`TrustTunnelGUI-<версия>-setup.exe`) с удалением через «Установленные приложения»
  и тихими режимами `--silent` / `--uninstall --silent`.
- Portable-версия: настройки и журналы хранятся в папке `data` рядом с программой.

### Изменено
- Автозапуск без прав администратора работает через раздел реестра `Run`, с правами — через Планировщик заданий.
- Новая структура репозитория: `src/`, `installer/`, `scripts/`, `client/`, `docs/`.

## 1.0.0

- Первая версия: интерфейс в стиле TrustTunnel Flutter Client — серверы, профили маршрутизации, настройки, трей.
- Импорт ссылки `tt://` и файла `.toml` через `setup_wizard.exe`.
- Корректная остановка клиента через Ctrl+C; пароли хранятся зашифрованными (DPAPI).
